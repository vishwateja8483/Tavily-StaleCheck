# StaleCheck offline v2 domain contract

Status: frozen implementation target for the independent offline milestone, not a live or authenticity claim. V1 input/config/report derivation and bytes remain unchanged; dispatch rejects unsupported or mixed versions without fallback.

## Versioned documents

- Review records retain the existing `schema_version: "1.0"`, `format: "human_attested_review"` contract. Conversion calls `validate_review`; attestations are supplied, never generated by conversion. An immediate prior record is mandatory for corrections. Older ancestors are not resolved; corrections neither erase nor temporally supersede prior statements.
- `review-to-evidence --input RECORDS --output FILE` takes `{schema_version:"2.0",format:"review_conversion",reviews:[{review,previous_review}]}`. `previous_review` is always present, either null or the supplied immediate record. Produces `{schema_version:"2.0",format:"reviewed_evidence",reviews:[...],evidence:[...]}`. One deterministic source/statement pair per distinct review digest. Embedded unreviewed acquisitions remain unchanged. Maximum 100 reviews and existing 2,000,000-byte file bound apply. Partial acquisition is allowed and disclosed; it is not silently completed.
- `verify --input REQUEST --output DIRECTORY` additionally accepts exact v2 request fields: `schema_version:"2.0"`, `format:"reviewed_lifecycle_claims"`, `answer_text`, `answer_date` (date or null), `verification_date`, `scope`, `claims`, `reviewed_evidence` (the converted document). Claims are explicit public structured claims, one to five, with id/text/subject/assertion/scope/public and optional as_of. No acquired prose becomes a claim automatically.
- V2 config uses package_version `0.2.0`, algorithm `reviewed-lifecycle-intervals-v2`, max_claims 5, network false, model null. V2 report has `schema_version:"2.0"` and `version:"0.2.0"`. Common report fields remain project_id/run_id/mode/title/summary/limitations/claims/evidence/answer_text/answer_date/verification_date/scope/warnings/input_sha256/config_sha256/usage. New report field `reviewed_evidence` retains conversion and review/acquisition provenance. `evidence` exactly equals its derived evidence array.
- V2 derived source retains id/title/url/content/content_sha256/retrieved_at/published_at/provenance/statements plus review_sha256/candidate_sha256/acquisition_sha256/extraction_method. Source provenance is `human_attested_acquisition`. Statements retain id/subject/assertion/scope/value/quote/effective_from/effective_to/annotation_provenance, plus `end_state`, UTF-8 quote_start_byte/quote_end_byte and review_sha256. `effective_to` is null unless end_state is dated. Unknown end never establishes active coverage; v1 null remains open-ended.

## Exported claim explanations

Each v2 report claim retains the common claim/verdict/reason/evidence_ids/citations/freshness fields, and adds `explanation` with exact fields `schema_version:"2.0"`, `reason_code`, `original_as_of` (null if omitted), `target_date`, `answer_date`, `verification_date`, `prior`, `current`. An assessment is `{date,state,support,contradiction,excluded}`; state is unavailable/no_coverage/supported/contradicted/conflict. References are `{evidence_id,statement_id,review_sha256}`; exclusions additionally carry reason_code (SUBJECT_MISMATCH, ASSERTION_MISMATCH, SCOPE_MISMATCH, UNKNOWN_START, UNKNOWN_END, NOT_YET_EFFECTIVE, ENDED). Current assessment always refers to target_date; prior refers to answer_date, or unavailable when null. Eligibility reason codes prevent these mechanical coverage assessments from implying a supported verdict for ambiguous/out-of-scope/future claims. Citations additionally expose end_state and review_sha256.

Conflict yields ABSTAIN. STALE requires a present-tense target, unconflicted support at answer_date, unconflicted contradiction at target and an active false statement starting strictly after answer_date. Publication/retrieval clocks never supply lifecycle dates. Report verification rederives every field.

## Comparison and bundle interchange

`compare --before DIR --after DIR --output FILE` independently verifies both frozen runs and writes a deterministic `schema_version:"2.0",format:"frozen_run_comparison"` document. `verify-comparison --before DIR --after DIR --input FILE` rederives it. Run references bind run_id and exact manifest/input/config/report SHA-256. Claim matching uses full semantic identity (subject/assertion/scope/original as_of, not reused IDs); ambiguous duplicate semantic identities are rejected. Causes are a list, allowing content/extraction/statement/policy/clock/provenance changes; added/removed claims are explicit. A time-only attribution requires changed clocks and identical other inputs apart from claim IDs. Comparison is input-difference attribution, not causal proof or authenticity.

`export-viewer DIRECTORY [DIRECTORY ...] --output FILE` verifies each run with StaleCheck's own verifier, then emits only the established envelope `{schema_version:"1.0",generated_at,runs:[{manifest,report,events}],annotations:[],limitations:[...]}`. Manifest and event schemas stay 1.0; v2 domain lives in report/schema and frozen input/config. Output is exclusive, safe-path checked, serialized and checked against 5*1024*1024 bytes BEFORE opening output. No truncation. Verification/export hashes establish local consistency, not signed authenticity. Comparison remains a separate verifiable document, not an invented envelope field.

## Trust and bounds

Provider published_at may be a publication-or-update estimate. Search content is a snippet; extract content is extracted text, not original publisher document bytes. Reviewer identity is a supplied claim; attestation proves neither authenticated authorship, semantic entailment, truth, nor complete review history. Synthetic demo attestations are explicitly invented. No live/network/credential access is part of this milestone. File/path/structural limits use package-local existing bounded validators.
