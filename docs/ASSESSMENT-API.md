# Local assessment API v1

Explicitly launched, single-user, loopback only. No CORS or public deployment. Static assets are public; **all** `/api/` reads, writes and downloads require `X-Assessment-Token`, supplied at launch in a URL fragment and retained only in page memory. Strip the fragment before making requests. Mutations also require exact same-origin `Origin` and `Content-Type: application/json`. No credentials or answers in URLs/storage/logs. Reload requires reopening the launch URL.

Every JSON response is an object. Errors: `{"error":"safe message"}`. Unknown fields, duplicate keys/headers, cross-site requests, transfer encoding, oversized bodies and invalid inputs are rejected. No retry is automatic. A creation 4xx response rejects that request without reserving new work (including invalid input, active-job conflict and capacity exhaustion); the browser permits edits and requires fresh consent. An uncertain transport, 5xx or malformed success-response outcome retains the original immutable input/idempotency key for explicit retry.

- `GET /api/capabilities`: `{mode: "demo"|"live", configured: boolean, configuration: {BIFROST_URL: boolean, BIFROST_MODEL: boolean, BIFROST_VIRTUAL_KEY: boolean, TAVILY_API_KEY: boolean, BIFROST_SEARCH_RELAY: boolean}, max_sessions: number, demo_input: Input|null}`. Presence is not connectivity. Live mode needs the first three settings and either `TAVILY_API_KEY` (searches go directly to Tavily) or `BIFROST_SEARCH_RELAY` (the name of a Bifrost relay: searches go through the gateway, authorised by the virtual key; the service then discards any Tavily key and reports it absent). Invalid configured credentials/origins/relay names keep live creation disabled. Demo never calls a provider.
- `POST /api/jobs`: `{idempotency_key: string, input: Input}`. Input has exactly `answer_text: string`, `verification_date: YYYY-MM-DD`, `answer_date: YYYY-MM-DD|null`, `primary_domains: string[]`, `max_claims: integer (1..8)`, `max_attempts: integer (1..25)`, `max_seconds: number (0..180]`, `consent: true`. Full answer goes to Bifrost, then selected claims/source excerpts; exact approved queries go to Tavily. Returns Job (201; identical retry 200). Different input under same key or another active job: 409. Launch-lifetime capacity: 429; no eviction or resumption.
- `GET /api/jobs/{id}`: Job.
- `POST /api/jobs/{id}/approval`: `{request: {queries: string[], primary_domains: string[], sha256: string}, approved: boolean}`. Compare the complete object canonically against this job's pending request under its lock. Identical prior decision is harmless; changed/late decision is 409. Never repeat extraction. Returns Job.
- `POST /api/jobs/{id}/cancel`: `{}`. Returns Job. Cancellation is cooperative; already sent requests may finish and be billed. `cancel_requested` retains the active slot until worker exit.
- `GET /api/jobs/{id}/report`: verified v4 report JSON. 409 until artifacts exist and verify.
- `GET /api/jobs/{id}/artifacts/{name}`: only `report.html`, `report.json`, `input.json`, `manifest.json`, `verified-run.zip`. The ZIP contains the exact verified run files and manifest, including the original answer. Unzip into an empty directory and pass that directory to `stalecheck verify-artifacts`. Verified afresh; fixed server-owned paths only. HTML generated using the existing escaped, script-free v4 renderer. Fetch with the authentication header and display through a sandboxed `srcDoc` frame (no scripts/same-origin permissions); downloads through a fetched Blob, never an unauthenticated navigation. The parent CSP permits only inline report styles and sandboxed frames, not inline script.

Job: `{id: string, mode: "demo"|"live", state: "extracting"|"awaiting_approval"|"researching"|"cancel_requested"|"completed"|"partial"|"declined"|"expired"|"cancelled"|"failed", remaining_seconds: number, approval: Request|null, stop_reason: string|null, attempts: number, artifacts: string[]}`. Service state is not a new v4 verdict. Completed means collection finished, not proof of truth. Partial/declined reports may also verify. Failed/cancelled/expired work preserves checkpoints, not a completed report.

Human review consumes the original journey deadline (maximum 180 seconds). Expiry during review or provider work raises a service interruption, checkpoints retained; no clock reset and no completed report is published after expiry. One collector invocation stays alive while its callback waits. Sessions, idempotency mappings and handler concurrency are bounded. Restart invalidates the token and never resumes unfinished work. The output root is a new exclusive launch directory; existing directories are never reused or removed.

## Input and launch guidance

Answers have an 8,000 Unicode-codepoint maximum. Dates must be valid calendar dates and the optional answer date must not follow the verification date. Domains must satisfy the acquisition contract: a bounded, unique list of lowercase public hostnames, not URLs. The browser trims/lowercases domain lines but never removes duplicates or extracts hosts from URLs. Local validation displays field errors before creating work; the server remains authoritative and keeps its sanitized error envelope.

Demo answer/dates/domains must exactly match `demo_input`. The UI loads them explicitly and makes them read-only; supported budget limits remain editable. Loading the fixture or editing a budget resets consent.

Startup validates packaged assets and binds the actual socket before reserving the exclusive output directory. For a port conflict use `--port 0`, or stop the conflicting service. Startup never deletes or reuses existing output. `doctor` remains offline and does not read credentials or verify connectivity.

Trust boundary: hostile web pages are denied authority; malware running as the same OS user is outside scope. No arbitrary commands, URLs, proxy endpoints or directory browsing. Secrets stay in the server process. Socket timeouts are cooperative, not a hard provider cancellation guarantee. Live compatibility must be demonstrated separately from demo tests.
